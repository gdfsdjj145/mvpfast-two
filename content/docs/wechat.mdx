MVPFast 的 PC 微信登录使用微信开放平台，手机微信内登录使用公众号网页授权。两个流程都由当前 Next.js 项目的 Vercel 服务端接口处理，不需要单独部署微信云托管服务。

## 登录配置

在 Vercel 项目的 Production 环境配置以下变量；AppSecret 仅供服务端读取，不要加 `NEXT_PUBLIC_` 前缀：

```text
NEXT_PUBLIC_SITE_URL=https://www.mvpfast.top
NEXT_PUBLIC_WECHAT_OPEN_APPID=网站应用 AppID
WECHAT_OPEN_APPID=网站应用 AppID
WECHAT_OPEN_APPSECRET=网站应用 AppSecret
NEXT_PUBLIC_WECHAT_APPID=公众号 AppID
WECHAT_MP_APPSECRET=公众号 AppSecret
```

公众号后台的网页授权域名应与 `NEXT_PUBLIC_SITE_URL` 的域名一致。手机登录从 `/api/wx/authorize` 发起，微信回到 `/api/wx/callback`；PC 登录使用微信开放平台扫码。回调校验一次性 `state`，再签发短时一次性登录票据。

## 微信支付配置

支付下单接口将通知地址设置为本站 `/api/wechat-pay-callback`。该路由使用微信支付公钥或微信支付平台证书验签，再用商户 APIv3 密钥解密通知。除现有商户号、商户 API 证书序列号和商户私钥外，还需配置：

```text
WECHAT_API_V3_KEY=商户平台设置的 32 字节 APIv3 密钥
WECHAT_PAY_VERIFY_KEY=微信支付公钥 PEM 或微信支付平台证书 PEM 全文
WECHAT_PAY_VERIFY_SERIAL=对应的 PUB_KEY_ID_... 或平台证书序列号
```

微信支付公钥和 ID 可在商户平台「账户中心 → API 安全」获取。`WECHAT_PAY_VERIFY_KEY` 可使用真实换行或字面量 `\\n` 存储。其 ID/序列号必须与通知请求头中的 `Wechatpay-Serial` 一致。`BEGIN PRIVATE KEY` 是商户请求签名私钥；与它配套的商户 API 证书不能用于微信通知验签。

当前项目的支付通知路由只负责验证和接收通知；现有页面仍通过服务端查单确认付款后创建订单和发放积分。若以后改为收到通知就自动履约，应先持久化待支付订单并实现幂等事务，不能仅依据浏览器提交的商品和金额发放权益。
